# ESG repair search

Локальный OpenAI-compatible сервис для поиска описанных ремонтов по конструктивной зоне. OpenWebUI использует модель `esg-repair-search` через `http://esg-api:8132/v1`.

## Безопасность источников

В режиме индексации исходные сетевые каталоги не монтируются в контейнер. Входом служат только ранее подготовленные локальные Markdown из `source_documents/`; SQLite и прочие производные данные находятся в `runtime/`. Путь исходного DOCX сохраняется в реестре только как метаданные для ссылки в ответе.

Предварительно DOCX были преобразованы напрямую из OOXML без MinerU и OCR. Этот этап не входит в текущий проход индексации.

## Индексация

Индексация выполняется в строгом порядке:

1. Из сохраненного каталога выбираются канонические документы по уникальному имени файла; все физические дубликаты сохраняются в реестре.
2. Индексатор читает ранее подготовленные локальные Markdown; исходные DOCX на этом этапе не открываются.
3. В Markdown структурно находятся разделы и подразделы с нормализованным заголовком `Описание ремонта`.
4. Из разделов удаляются рисунки, ссылки на рисунки и нерелевантные таблицы. Таблицы с полями `Область ремонта`, `Зона ремонта` или `Расположение` преобразуются в обычный текст и сохраняются.
5. Очищенный текст делится на чанки и сразу индексируется. LLM при индексации документов не используется.
6. Документы без такого раздела получают статус `no_repair_section`.

Полный Markdown сохраняется, но не входит в поисковый индекс.

Запуск по сохраненному каталогу:

```bash
curl -X POST http://localhost:8132/api/ingest/run \
  -H 'Content-Type: application/json' -d '{}'
```

Ручное обновление каталога и запуск:

```bash
curl -X POST http://localhost:8132/api/sources/refresh \
  -H 'Content-Type: application/json' -d '{}'
```

Отмена после завершения текущей операции над документом:

```bash
curl -X POST http://localhost:8132/api/ingest/cancel \
  -H 'Content-Type: application/json' -d '{}'
```

## Статусы

```bash
curl http://localhost:8132/api/ingest/status
curl http://localhost:8132/api/documents/summary
curl 'http://localhost:8132/api/documents?status=no_repair_section&limit=100&offset=0'
curl -o esg-documents.csv http://localhost:8132/api/documents.csv
```

Реестр содержит каждый физический путь, канонический документ, статус, причину, Markdown-путь, количество найденных разделов и количество ремонтов.

## Поиск

Маленькая Qwen структурирует пользовательский запрос. Документные чанки остаются текстовыми; финальная модель проверяет совместимость зоны по очищенному тексту раздела.

Лексический и векторный поиск, reranker и большая финальная LLM работают только с очищенными чанками раздела `Описание ремонта`.
