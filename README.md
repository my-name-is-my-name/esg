# ESG repair search

Локальный OpenAI-compatible сервис для поиска описанных ремонтов по конструктивной зоне. OpenWebUI использует модель `esg-repair-search` через `http://esg-api:8132/v1`.

## Безопасность источников

Оба каталога источников монтируются в контейнер только для чтения (`:ro`). Сервис читает из них только DOCX с токеном `TR` или `SR` в имени. Он никогда не создает, не изменяет, не перемещает и не удаляет исходные файлы. Markdown, SQLite и прочие производные данные находятся только в локальных `source_documents/` и `runtime/`.

DOCX преобразуются напрямую из OOXML. MinerU и OCR для DOCX не используются; ошибка прямого чтения получает статус `conversion_failed`.

## Индексация

Индексация выполняется в строгом порядке:

1. Из сохраненного каталога выбираются канонические документы по уникальному имени файла; все физические дубликаты сохраняются в реестре.
2. Все канонические DOCX преобразуются в Markdown.
3. В Markdown структурно находятся разделы и подразделы с нормализованным заголовком `Описание ремонта`.
4. Документы без такого раздела получают статус `no_repair_section` и не передаются LLM.
5. Только после окончания конвертации большая LLM извлекает из найденных разделов `repairs[]` и `zones[]`.
6. На каждый канонический документ создается не более одной записи в коллекции `esg_repair_documents_v1`.

Полный Markdown сохраняется, но не входит в поисковый индекс. LLM-результаты кешируются по содержимому и версии промпта.

Запуск по сохраненному каталогу:

```bash
curl -X POST http://localhost:8132/api/ingest/run \
  -H 'Content-Type: application/json' -d '{}'
```

Ручное обновление каталога и запуск:

```bash
curl -X POST http://localhost:8132/api/sources/refresh \
  -H 'Content-Type: application/json' -d '{}'
```

Отмена после завершения текущей операции над документом:

```bash
curl -X POST http://localhost:8132/api/ingest/cancel \
  -H 'Content-Type: application/json' -d '{}'
```

## Статусы

```bash
curl http://localhost:8132/api/ingest/status
curl http://localhost:8132/api/documents/summary
curl 'http://localhost:8132/api/documents?status=no_repair_section&limit=100&offset=0'
curl -o esg-documents.csv http://localhost:8132/api/documents.csv
```

Реестр содержит каждый физический путь, канонический документ, статус, причину, Markdown-путь, количество найденных разделов и количество ремонтов.

## Поиск

Маленькая Qwen преобразует запрос пользователя в ту же схему `Zone`, которая заранее сохранена для документов. Интервалы сравниваются структурно и включительно: запрос `6-7` пересекается с диапазоном документа `2-10`. Координаты разных ремонтов одного документа не объединяются.

Лексический и векторный поиск, reranker и большая финальная LLM работают только с компактными документными записями ремонтов. Финальная LLM получает дословные проверенные фрагменты раздела `Описание ремонта`.
